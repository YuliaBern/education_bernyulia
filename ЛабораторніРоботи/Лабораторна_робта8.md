**Мета:** Впровадити систему моніторингу та централізованого логування

**Короткі теоретичні відомості**

Моніторинг і логування — ключові компоненти спостережуваності (observability) розподілених мікросервісних систем.

**Моніторинг метрик**

Prometheus збирає числові метрики з мікросервісів через HTTP-ендпоінт /metrics (формат OpenMetrics). Метрики зберігаються у часовій базі даних і дозволяють відстежувати:

- використання CPU/RAM/диску
- кількість запитів, помилок 4xx/5xx
- латентність (час відповіді)
- кастомні показники (оброблені події, розмір черги тощо)

Grafana підключається до Prometheus і візуалізує метрики у вигляді дашбордів, графіків, таблиць та алертів.

**Централізоване логування**

Логи з усіх контейнерів і сервісів збираються в одну систему. Найпоширеніший стек:

- Fluentd / Fluent Bit / Logstash — агент збору логів
- Elasticsearch — зберігання та пошук
- Kibana — веб-інтерфейс, дашборди, пошук

**Три стовпи спостережуваності**

- Метрики (Metrics) — що відбувається
- Логи (Logs) — чому сталося
- Трейси (Traces) — шлях запиту через усі сервіси (OpenTelemetry, Jaeger, Zipkin)

2\. Налаштувати збір метрик з мікросервісів.

***construction_service*** 
**main.py**
```python
from fastapi import FastAPI
from prometheus_client import Counter, Histogram, generate_latest
from prometheus_client.exposition import CONTENT_TYPE_LATEST
from fastapi.responses import Response
import pika
import json
import time
import os

app = FastAPI()

REQUEST_COUNT = Counter(
    "http_requests_total",
    "Total HTTP requests",
    ["method", "endpoint"]
)

REQUEST_LATENCY = Histogram(
    "http_request_latency_seconds",
    "Request latency"
)

rabbit_host = os.getenv("RABBITMQ_HOST", "rabbitmq")

@app.post("/objects")
@REQUEST_LATENCY.time()
def create_object(obj: dict):
    REQUEST_COUNT.labels("POST", "/objects").inc()

    connection = pika.BlockingConnection(
        pika.ConnectionParameters(host=rabbit_host)
    )
    channel = connection.channel()
    channel.queue_declare(queue="construction_events")

    event = {
        "type": "construction_created",
        "data": obj
    }

    channel.basic_publish(
        exchange="",
        routing_key="construction_events",
        body=json.dumps(event)
    )

    connection.close()
    return {"message": "Object created and event published"}

@app.get("/metrics")
def metrics():
    return Response(generate_latest(), media_type=CONTENT_TYPE_LATEST)

```

***analytics_service*** 
**main.py**
```python
import pika
import json
import time
import os

RABBITMQ_HOST = os.getenv("RABBITMQ_HOST", "rabbitmq")
QUEUE_NAME = "construction_events"

def callback(ch, method, properties, body):
    event = json.loads(body)
    print(" Analytics received event:", event)

def connect():
    while True:
        try:
            print(" Connecting to RabbitMQ...")
            connection = pika.BlockingConnection(
                pika.ConnectionParameters(host=RABBITMQ_HOST)
            )
            print(" Connected to RabbitMQ")
            return connection
        except pika.exceptions.AMQPConnectionError:
            print(" RabbitMQ not ready, retrying in 5 seconds...")
            time.sleep(5)

connection = connect()
channel = connection.channel()
channel.queue_declare(queue=QUEUE_NAME)

channel.basic_consume(
    queue=QUEUE_NAME,
    on_message_callback=callback,
    auto_ack=True
)

print(" Analytics Service waiting for events...")
channel.start_consuming()


```

**Висновки**

У ході виконання лабораторної роботи було впроваджено систему моніторингу та логування для мікросервісної архітектури. Було налаштовано збір метрик з REST-сервісів за допомогою Prometheus, а також їх візуалізацію у Grafana. Система дозволяє відстежувати кількість HTTP-запитів, час відповіді сервісів та загальний стан компонентів у режимі реального часу.

Під час роботи було перевірено коректність взаємодії між сервісами, чергою повідомлень RabbitMQ та системою моніторингу. Отримані результати підтверджують, що моніторинг забезпечує прозорість роботи системи та дозволяє оперативно виявляти проблеми у розподіленому середовищі.

Таким чином, поставлену мету лабораторної роботи досягнуто, а впроваджені інструменти моніторингу є ефективними для контролю та аналізу роботи мікросервісів.

**ЛАБОРАТОРНА РОБОТА № 4**

**Тема:** Технологічна архітектура 

**Мета:**  Розробити схему технологічного забезпечення РПС.

**Короткі теоретичні відомості**

Технологічна архітектура — це повний опис «як саме» працює система на рівні інфраструктури, платформ і інструментів.

Вона включає чотири основні шари:

1. Інфраструктурний рівень

   Фізичні або віртуальні сервери, мережа, сховища (AWS EC2, VPC, EBS тощо).

1. Платформний рівень

   Контейнеризація (Docker), оркестрація (Kubernetes), брокери повідомлень (Kafka), бази даних (PostgreSQL, MongoDB, Redis), системи моніторингу (Prometheus + Grafana).

1. Рівень застосунків

   Мікросервіси (Equipment Service, Allocation Service, Maintenance Service), API Gateway (Traefik), механізми авторизації (JWT), кешування.

1. Рівень доступу користувачів

   Мобільні додатки, веб-інтерфейси, push-сповіщення.

**Сучасна практика:**

- Усе пакується в Docker-контейнери.
- Розгортається та керується через Kubernetes (або його хмарні аналоги EKS, GKE, AKS).
- Використовуються керовані сервіси хмар (RDS, MSK, ElastiCache), щоб не обслуговувати інфраструктуру вручну.
- Забезпечується автоматичне масштабування (HPA + Cluster Autoscaler), безпечне оновлення (rolling update, blue-green), повна спостережуваність (metrics, logs, traces).

**Завдання до роботи згідно варіанту**

Предметна область: Система керування технікою на будівельному майданчику

**Механізми забезпечення стійкості**

|**Механізм**|**Реалізація**|**Надані можливості**|
| :- | :- | :- |
|Балансування|Nginx reverse proxy|Розподіл запитів між сервісами|
|Резервування|Docker перезапускає контейнери (restart: always)|Сервіси автоматично відновлюються після збою|
|Кешування|Redis|Зменшення навантаження на PostgreSQL|
|Черги / події|Kafka|Асинхронність між сервісами|
|Резервні копії БД|pg\_dump (ручні)|Бекапи для моделі|

**Висновки**

У лабораторній роботі побудовано  технологічну архітектуру розподіленої системи.

Архітектура базується на:

- Docker + Docker Compose
- Nginx як API Gateway,
- PostgreSQL та Redis,
- Kafka для подій,
- трьох мікросервісах (Equipment, Allocation, Maintenance).

Побудована топологія демонструє, як сервіси взаємодіють між собою, з базами даних та брокером подій. Система є стійкою завдяки перезапуску контейнерів, кешуванню та асинхронній обробці подій.

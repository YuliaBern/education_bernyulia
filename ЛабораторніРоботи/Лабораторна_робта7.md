# ﻿**ЛАБОРАТОРНА РОБОТА № 7**

**Тема:** Оркестрація мікросервісів 

**Мета:** Навчитися керувати кількома контейнерами

**Короткі теоретичні відомості**

Оркестрація контейнерів — це автоматизоване керування життєвим циклом великої кількості контейнеризованих мікросервісів: розгортання, масштабування, оновлення, моніторинг і автоматичне відновлення при збоях.

Docker Compose — інструмент для локальної розробки та тестування. У одному файлі docker-compose.yml описуються всі сервіси системи (API, бази даних, брокери повідомлень, моніторинг тощо), їх залежності, порти, змінні середовища та томи. Запуск однією командою: docker compose up -d.

Kubernetes — промислова платформа оркестрації. Основні об’єкти:

- Pod — найменша одиниця (один або кілька контейнерів);
- Deployment — керує кількістю реплік Pod-ів та оновленнями;
- Service — надає стабільний доступ до Pod-ів (ClusterIP, NodePort, LoadBalancer);
- Ingress — зовнішній HTTP/HTTPS-доступ;
- ConfigMap / Secret — конфігурація та чутливі дані;
- PersistentVolume — збереження стану.

Переваги оркестрації:

- автоматичне горизонтальне масштабування (HPA);
- самовідновлення (restart та заміна Pod-ів при збої);
- rolling update та blue-green deployment без простою;
- розподіл навантаження між вузлами кластера;
- централізований моніторинг і логування.

У будівельній сфері оркестрація дозволяє швидко розгортати та масштабувати системи моніторингу об’єктів, аналітики даних з IoT-сенсорів, дашборди та сповіщення, забезпечуючи високу доступність і відмовостійкість навіть при значному зростанні кількості мікросервісів та навантаження.

**Завдання до роботи згідно варіанту** 

1\. Розробити docker-compose.yml для запуску кількох сервісів. 

2\. Налаштувати мережеві зв’язки між контейнерами. 

3\. Перевірити роботу системи через REST API.

**Протоколи розв’язання задач** 

Для оркестрації мікросервісів використано Docker Compose. У файлі docker-compose.yml описано чотири сервіси: REST API, сервіс аналітики, база даних PostgreSQL та брокер повідомлень RabbitMQ. Docker Compose автоматично створив спільну мережу, налаштував залежності між контейнерами та забезпечив їх коректний запуск. Роботу системи перевірено через REST API та логи контейнерів.

***construction_service*** 
**main.py**
```python
from fastapi import FastAPI
import pika
import json

app = FastAPI(title="Construction Service")

def publish_event(event: dict):
    connection = pika.BlockingConnection(
        pika.ConnectionParameters(host="rabbitmq")
    )
    channel = connection.channel()
    channel.queue_declare(queue="construction_events")

    channel.basic_publish(
        exchange="",
        routing_key="construction_events",
        body=json.dumps(event)
    )

    connection.close()

@app.post("/objects")
def create_object(obj: dict):
    event = {
        "type": "construction_created",
        "data": obj
    }

    publish_event(event)

    return {"message": "Object created and event published", "event": event}

```

***analytics_service*** 
**main.py**
```python
import pika
import json

def callback(ch, method, properties, body):
    event = json.loads(body)
    print("Received event:", event)

connection = pika.BlockingConnection(
    pika.ConnectionParameters(host="rabbitmq")
)

channel = connection.channel()
channel.queue_declare(queue="construction_events")

channel.basic_consume(
    queue="construction_events",
    on_message_callback=callback,
    auto_ack=True
)

print("Analytics Service waiting for events...")
channel.start_consuming()

```
**requirements.txt**
```txt
pika

```
**Dockerfile**
```
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY main.py .

```
